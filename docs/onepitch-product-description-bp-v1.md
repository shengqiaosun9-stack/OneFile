# OnePitch 产品说明

来源：`OnePitch_商业企划书_v1.0.pdf`
整理日期：2026-05-31

## 1. 产品定位

OnePitch 是一个面向 AI/OPC 早期项目的路径诊断与结构化档案工作台。

它要解决的不是单纯“生成一张好看的项目卡”，而是帮助项目在进入园区、政策、订单、投资、技术交付、内容曝光或经营系统之前，先完成一次清晰的项目理解、路径判断和材料准备。

一句话说明：

OnePitch 帮 AI/OPC 项目先讲清楚自己，再判断下一步应该找园区、技术、订单、融资、内容曝光，还是先补材料。

## 2. 核心问题

AI 降低了个人、小团队和超级个体启动项目的门槛，但项目被外部资源方理解的速度没有同步提升。

早期项目常见问题包括：

- 创始人能口头讲项目，但材料无法让外部快速判断。
- BP、聊天记录、私信、路演稿、朋友圈信息分散。
- 园区、投资人、AI 技术服务商、企业客户看到项目后不知道是否值得继续聊。
- 项目方经常误判自己当前真正需要的资源。
- AI 在项目中到底是核心能力、交付工具、内部提效，还是概念包装，常常讲不清楚。

OnePitch 的核心价值是建立一个“项目理解层”：先把项目讲清楚，再决定它该被谁看、该走哪条路径、该补什么材料。

## 3. 目标用户

### 项目方

适合个人创业者、超级个体、小团队、传统产业经营者、高校项目和 AI 服务商。

他们可能已经有想法、Demo、客户、订单、收入、场景、技术需求或资源诉求，但缺少清晰表达和路径判断。

### 园区 / OPC 社区

他们收到大量 BP 和项目线索，但缺少标准化初筛材料。OnePitch 帮他们更快判断项目是否有商业闭环、是否适合入驻、是否值得继续沟通。

### AI 技术服务商

他们需要明确的业务需求、数据情况、技术边界、部署要求和交付目标。OnePitch 可以把项目方模糊需求整理成技术需求卡。

### 投资人与产业资源方

他们没有时间看大量原始 BP，需要先看到结构清楚、证据明确、阶段清晰的项目判断摘要。

### 内容与商务资源方

他们需要判断哪些项目、园区、产业案例具有样本价值，适合被访谈、拍摄或包装成产业观察内容。

## 4. 产品核心逻辑

OnePitch 的工作流分为五步：

1. 收集项目原始信息
   - 项目介绍
   - BP
   - 聊天记录
   - 访谈纪要
   - 园区反馈
   - 资源需求

2. 进行路径诊断
   - 判断项目现在适合找园区、技术、订单、融资、内容曝光，还是先补材料。
   - 判断项目是否有客户、订单、收入、交付、AI 相关性和资源诉求。

3. 生成结构化项目档案
   - 项目一句话
   - 当前阶段
   - 目标客户
   - 商业闭环
   - AI 相关性
   - 资源需求
   - 材料缺口
   - 下一步建议

4. 输出多版本材料
   - 园区版
   - 投资人版
   - 技术团队版
   - 企业客户版
   - 内容访谈版
   - 项目卡 / 信任官网

5. 记录反馈并持续更新
   - 资源方问了什么
   - 项目方怎么回答
   - 材料如何修改
   - 是否推荐、是否继续聊、是否转化为合作

## 5. 核心模块

### 5.1 首页：项目路径诊断入口

首页不应该只强调“生成项目卡”，而应强调“先判断项目路径”。

建议表达：

- 标题：先判断项目路径，再生成对外材料
- 副标题：输入项目介绍、BP、聊天记录或访谈纪要，OnePitch 会帮你判断当前更适合找园区、技术、订单、融资，还是先补材料，并生成第一版项目档案。
- 主按钮：开始项目诊断

### 5.2 项目诊断表单

诊断表单收集六类信息：

- 项目基本信息
- 项目阶段
- 商业闭环
- AI 相关性
- 当前资源需求
- 现有材料

重点不是让用户填很多字段，而是抓住判断路径所需的信息。

### 5.3 诊断结果页

诊断结果页是从免费工具转向付费服务的关键页面。

它应输出：

- 项目一句话
- 项目表达完整度
- 园区初筛准备度
- 技术需求清晰度
- 资源连接准备度
- 推荐路径
- 材料缺口
- 下一步建议

### 5.4 项目档案页

项目档案页是 OnePitch 的核心资产。

它应包含：

- 项目概览
- 商业模式
- 目标客户
- 当前进展
- 关键数据
- AI 相关性
- 资源需求
- 材料附件
- 路径建议
- 资源方反馈
- 版本记录

关键要求：保留原文证据。AI 结构化不能丢掉创始人原始语义，每个重要判断最好能追溯到 BP 原文、访谈摘录或聊天记录。

### 5.5 多版本输出页

同一个项目给不同对象看的重点不同。

OnePitch 应允许用户选择“我要发给谁”，再生成对应版本：

- 园区版：商业闭环、营收订单、入驻诉求、AI 相关性、需要园区支持什么。
- 投资人版：市场切口、增长数据、商业模式、团队能力、竞争壁垒、融资用途。
- 技术团队版：当前系统、技术需求、数据来源、部署要求、预算范围、交付边界。
- 企业客户版：解决什么业务问题、落地效果、案例、交付流程、合作方式。
- 内容访谈版：创始人故事、项目切口、行业变化、争议点、可传播标题。

### 5.6 资源路径页

资源路径页回答：这个项目下一步适合连接谁。

可能路径包括：

- 园区 / OPC 社区
- AI 技术服务商
- 企业客户 / 订单方
- 投资人 / 产业资源方
- 内容曝光
- 先补材料

每条路径都应说明：

- 为什么适合
- 需要准备什么材料
- 下一步动作是什么

### 5.7 项目库页

项目库是 OnePitch 的项目雷达。

它应支持按以下维度筛选：

- 阶段
- 行业
- 资源需求
- 是否有营收
- 是否适合园区
- 是否适合技术服务
- 是否适合内容访谈
- 是否已推荐
- 是否有反馈

项目卡片应展示：

- 项目名
- 一句话
- 当前路径
- 准备度评分
- 资源需求
- 最近反馈
- 下一步

### 5.8 资源方反馈页

资源方反馈页记录园区、投资人、技术团队、企业客户问了什么，项目方怎么答，我如何优化答案，后续状态如何。

这是 OnePitch 长期形成数据壁垒的关键模块。

## 6. 数据对象

OnePitch 应沉淀以下核心对象：

- Projects：项目档案
- People：创始人、技术方、资源方、投资人、园区方
- Organizations：园区、协会、服务商、企业、学校、产业平台
- Needs：项目当前需求
- Offers：资源方可提供的能力
- Interactions：访谈、私信、会议、电话、线下见面
- Contents：内容样本、访谈、产业观察
- Feedback：园区、技术团队、投资人、客户的反馈
- NextActions：下一步动作

其中 Projects 是业务中心，People / Organizations / Needs / Offers 是资源网络，Interactions / Feedback / NextActions 是推进记录。

## 7. 商业模式

OnePitch 的商业路径不是单一 SaaS，而是轻产品 + 重服务。

### 7.1 项目方付费

近期最容易形成现金流。

服务包包括：

- 项目初诊
- 项目结构化档案
- BP / 路演 / 园区材料重构
- 资源推进陪跑

### 7.2 园区 / OPC 社区付费

园区前期更适合作为反馈节点，不宜一开始强推收费。

后续可提供：

- 项目初筛服务
- 项目档案标准化
- 入驻前诊断
- 活动 / 路演项目征集
- 园区项目看板

### 7.3 AI 服务商 / 技术交付分成

OnePitch 负责前端需求诊断，把业务流程、技术诉求、预算边界、交付目标和风险点整理成技术需求卡，再推荐给合适服务商。

收入可以来自：

- 咨询费
- 转介绍费
- 交付分成
- 联合服务包

### 7.4 内容服务收入

内容不是硬广，而是产业观察。

内容服务包括：

- 创始人访谈
- 园区观察
- 项目样本内容
- 活动内容服务
- AI 进入产业现场案例
- 商业访谈
- 专题复盘

### 7.5 长期产品化收入

当项目结构化服务足够多后，OnePitch 可以逐步产品化：

- 项目路径诊断 SaaS
- 项目档案工作台
- 项目档案展示页 / 信任官网
- 园区项目看板
- AI 服务商能力库
- 项目库订阅
- 资源方项目预览
- 多版本材料生成
- 项目反馈和对接记录系统

## 8. 当前最小产品形态

从商业计划书看，当前最应该保留和推进的是一个本地优先的 OnePitch 工作台，而不是大而全 SaaS。

最小可用形态：

- 本地 `/ops` 作为后台入口
- 支持项目、人物、机构、需求、供给、沟通、内容和行动项记录
- 支持项目路径诊断字段
- 支持从原始材料生成结构化项目档案
- 支持生成半公开项目卡和多版本材料
- 支持记录资源方反馈
- 支持导出、备份和持续更新

公开项目卡、项目库和分享页可以保留，但它们应作为输出层，而不是当前唯一主产品。

## 9. 产品边界

OnePitch 不做：

- 不抢政策查询工具的位置
- 不抢订单撮合平台的位置
- 不抢一人公司经营管理后台的位置
- 不做单纯 BP 打分工具
- 不承诺融资成功、入园成功、政策获取、投资收益或就业结果

OnePitch 做的是：

- 项目被推荐前的路径判断
- 项目被资源方理解前的结构化准备
- 项目推进过程中的反馈记录和版本更新
- 项目与资源之间的前端筛选和翻译

## 10. 未来 30 天产品重点

接下来 30 天最重要的是验证路径诊断链路。

建议优先级：

1. 强化项目路径诊断入口
2. 完成 5-10 个真实项目诊断
3. 至少形成 3 个完整项目档案
4. 给 2-3 个园区或资源方试看，收集反馈
5. 固化三个服务包：项目初诊、项目结构化档案、资源推进陪跑
6. 把所有项目、反馈、需求和下一步统一沉淀到 OnePitch

## 11. 一句话总结

OnePitch 是 AI/OPC 项目进入资源网络之前的标准化准备层。

它看见项目，理解需求，判断路径，整理档案，连接资源，并把每次项目表达、反馈和对接沉淀为长期数据资产。
